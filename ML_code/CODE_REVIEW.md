2. `data_fastcharge_mlp` 确为固定超参数的 MLP 训练与评估脚本。训练 StandardScaler 只拟合训练集，早停依据验证 RMSE，测试集用于训练后的评估。
3. 两个 prediction 均会加载 SMI-TED、生成候选 embedding、拼接工况并加载模型三件套；网络结构及对应超参数与训练文件一致。默认入口可读行内工况，缺失时回落至 25 °C、4C；0530 入口固定 25 °C、5C，不是第二个不同结构的训练模型。
4. 三件套为 `best_model_fixed.pth,best_scaler_fixed.pkl,best_features.npy`；当前训练保存全部特征索引。
5. `generate_place` 是基于质量分数的带约束随机采样，不是完整网格穷举。seed=2026，目标 2,000,000 行，最大尝试数 100,000,000，最近 300,000 条哈希去重。

## 组成换算的适用边界

以下是在代码中识别的边界，不代表原论文数据已经受到这些问题影响。是否影响真实输入，需查看实际数据或处理记录。

- `parse_ratio` 把 `1m` 和 `1M` 都识别成摩尔浓度 M，未区分质量摩尔浓度 m。
- 全部输入为 mol%/裸数字时直接归一化；若溶剂是裸数字而盐为 M，则兜底分支会返回仅溶剂的归一化结果，盐未计入。混合单位不一定得到完整组成。
- `wt%溶剂+M盐` 使用 100 g 溶剂和 100 mL 溶液两个基准；没有溶液密度/体积关系时不能视作严格换算。体积相加与按固体盐密度扣体积也属于近似假设。
- 两个 wt% 添加剂分别独立求质量，不能保证两者同时满足相对于最终总质量的原始百分数定义。
- 一般分支只处理 M 型锂盐；某些未识别比例、物性缺失或不支持单位会跳过组分；不能只检查结果“归一化为1”就认为组成完整。
- 槽位列不存在或比例缺失时，序列脚本会用 `O<sep>0` 填充；未匹配组分缩写在 replace 中原样保留。建议先核对实际中间表，不直接串接运行。

以上算法未在本次仓库整理中擅自改写，避免改变作者原始数据处理。需先识别实际输入涉及哪些分支，再确定是否需要修改与重新核对相关结果。

## 候选采样设置与论文措辞

- 正常子空间 `x1+x2>=0.65` 是**质量分数**限制；`ACADEMIC_HIGH_FUNC` 分支不执行这一最低值约束。不可统一写成所有候选 `x1+x2>=0.60` 或按摩尔分数限制。
- VC/DTD 的 x4 从 0 和 0.02 中采样，即质量分数0或2 wt%；辅助盐 x6=0.01，实际是1 wt%。原脚本“0.01 wt%”注释已经修正，数值没有改变。
- 功能组分和盐的比例按原脚本不同分支离散采样。最近窗口去重不等于全局唯一配方计数，也不合并仅槽位排序不同的化学等价配方。
- 脚本仍保留原来的全部采样规则。不能根据本次核查直接断言这就是生成论文最终候选集合的唯一历史版本。

- 当前按记录分层随机划分，没有按文献/配方分组。同一配方多倍率记录可能跨集合；是否存在需用样本ID检查。测试结果的外推含义应与这一划分方式一致。
- 未提供超参数搜索过程，不能从固定参数脚本反推参数选择是否独立于测试集。
- 训练代码计算了 data_fp，但未写入文件；CONFIG 中 REPORT_CSV 未被实际使用。误差表保留 original_index，可与原始 X/y 顺序对应；没有数据时不能独立重建这些对应关系。
- 两个预测脚本未显式 smited.eval()，但现已确认实际 load_smi_ted 在加载后调用 model.eval()，extract_embeddings 也调用 encoder.eval()。真实数值复现仍依赖相同 checkpoint、词表和软件环境。
- 默认预测脚本找不到已知序列列名时会取最后一列；5C版本会报错。5C入口按秒生成输出时间戳并追加写 CSV；同秒重跑或模块内重复调用可能混合输出，运行时使用独立输出目录。
- 完整训练、真实模型加载和真实 SMI-TED 编码尚未运行；离线验证范围见 verification.json。离线测试中的临时数据都是合成输入，不是作者实验或文献数据，也未加入发布数据目录。

## 新增编码与检查文件的核查

## 新增 load.py 的核查

- 已将提供的 load.py 原字节复制到 external/smi_ted_light/load.py。存在 load_smi_ted 与 encode_raw，函数签名与训练编码、两份预测脚本相匹配。未运行其深度学习入口。
- load_smi_ted 读取词表和 checkpoint，构建模型并 model.eval()。extract_embeddings 直接进行 tokenizer、Transformer encoder 和 autoencoder 编码；encode_raw 不调用 RDKit 的 normalize_smiles，返回前 detach 并重新构造 Tensor。
- n_embd 和 max_len 从 checkpoint 的 hparams 读取，不能仅凭注释证明当前权重是768维。tokenize 设置 truncation=True、max_length=self.max_len；真实配方是否触发截断需结合 checkpoint 和词表检查。
- 输入原字符串未经 RDKit 规范化，不等于 <sep> 是独立特殊 token。实际 PATTERN 使用 SMILES 正则；单独测试 _tokenize 所用正则，<sep> 分成 s、p、>，41.10000 按数字字符与小数点切分。不能在 Methods 写“以已注册的专用分隔 token 编码”，除非有另一份实际实现支持。此次未修改分词规则，以免改变历史特征。
- 实现根据 torch.cuda.is_available 自动启用 CUDA。预测脚本的 DEVICE=cpu 并不保证该 loader 的全部编码步骤都只在CPU执行；这不影响 MLP 自己的设备设置，但应准确记录实际环境。
- fast_transformers 是导入命名空间，其实际安装包/分支尚未查验，暂不提供猜测的版本或安装命令。
- 同批名为 pd、np 的文件经格式和像素读取确认是终端截图（PostScript），没有加入代码仓库；它们不构成 NumPy/Pandas 库、NPY数组或模型产物。
